# Контракт main-B2B ↔ ai-service

Версия контракта: `v1`. Источник истины на стороне main-B2B — `services/b2b-service/internal/infra/aiservice/client.go`.

## Взаимодействие

- Транспорт: HTTP/JSON, кодировка UTF-8.
- В MVP вызов синхронный: фоновый воркер main-B2B отправляет запрос и ждёт ответ.
  Асинхронность обеспечивает очередь задач main-B2B в Postgres. В проде вызов заменяется
  брокером сообщений с гарантией доставки, схема payload сохраняется.
- Таймаут ожидания ответа на стороне main-B2B — 90 с (`AI_SERVICE_TIMEOUT`).
- Успехом считается только ответ `200 OK` с валидным телом. Любой другой исход (сетевая ошибка,
  таймаут, не-200, невалидное тело) — сбой. main-B2B повторяет запрос с экспоненциальной
  задержкой (5 с, 10 с, 20 с, … до 5 мин), всего до 5 попыток, после чего прекращает попытки
  и логирует ошибку. Кейс остаётся в статусе `draft`.
- Один и тот же `case_id` может прийти повторно (ретраи). ai-service не должен хранить
  состояние между вызовами или полагаться на единственность запроса.
- Обе стороны игнорируют неизвестные поля — это позволяет расширять контракт без синхронного
  релиза.

## Запрос

`POST /v1/assessments`, `Content-Type: application/json`

Данные деперсонализированы: ФИО, контакты, идентификаторы пациента и исследования
в ai-service не передаются.

| Поле | Тип | Обязательно | Описание |
|---|---|---|---|
| `case_id` | string (UUID) | да | Идентификатор кейса в main-B2B, только для корреляции и логов |
| `study.modality` | `CT` \| `DX` \| `MG` | да | КТ / рентгенография / маммография |
| `study.body_site` | string | да, может быть `""` | Область исследования |
| `study.performed_at` | string (RFC 3339) | да | Дата и время исследования |
| `conclusion` | string | да | Заключение ИИ по исследованию, свободный текст; стиль оформления может отличаться |
| `patient.age` | integer | да | Полных лет на момент запроса |
| `patient.sex` | `male` \| `female` | да | Пол |
| `current_recommendations` | array | да, может быть `[]` | Услуги, уже рекомендованные пациенту по предыдущим подтверждённым кейсам — не дублировать |
| `current_recommendations[].code` | string | да | Код услуги из каталога (`""` — услуги нет в клинике) |
| `current_recommendations[].name` | string | да | Название услуги |
| `visits` | array | да, может быть `[]` | Прошедшие посещения из МИС |
| `visits[].service_code` | string | да | Код услуги |
| `visits[].service_name` | string | да | Название услуги |
| `visits[].visited_at` | string (RFC 3339) | да | Дата посещения |
| `appointments` | array | да, может быть `[]` | Будущие записи из МИС |
| `appointments[].service_code` | string | да | Код услуги |
| `appointments[].service_name` | string | да | Название услуги |
| `appointments[].scheduled_at` | string (RFC 3339) | да | Дата записи |

Массивы всегда передаются, `null` не используется.

```json
{
  "case_id": "39e61250-869e-4a3c-95a4-b16428e14332",
  "study": {
    "modality": "MG",
    "body_site": "breast",
    "performed_at": "2026-10-01T09:00:00Z"
  },
  "conclusion": "В верхне-наружном квадранте левой молочной железы образование неправильной формы 12 мм с нечёткими контурами. Заключение: BI-RADS 4.",
  "patient": { "age": 52, "sex": "female" },
  "current_recommendations": [],
  "visits": [
    { "service_code": "MG-SCREENING", "service_name": "Маммография (скрининг)", "visited_at": "2025-09-15T08:30:00Z" }
  ],
  "appointments": []
}
```

## Ответ

`200 OK`, `Content-Type: application/json`

| Поле | Тип | Обязательно | Описание |
|---|---|---|---|
| `urgency` | `normal` \| `planned` \| `priority` \| `emergency` | да | Срочность кейса: Норма / Плановый / Приоритетный / Неотложный |
| `catalog_version` | string, непустая | да | Версия каталога услуг, на основе которой выданы рекомендации |
| `guidelines_version` | string, непустая | да | Версия клинических рекомендаций Минздрава |
| `recommendations` | array | да, может быть `[]` | Рекомендации; порядок в массиве — порядок показа врачу |
| `recommendations[].service_code` | string | да | Код услуги из каталога клиники; `""` — услуги нет в клинике |
| `recommendations[].service_name` | string, непустая | да | Название услуги или профильного специалиста |
| `recommendations[].importance` | `high` \| `low` | да | Предварительная метка важности; врач подтверждает или меняет |
| `recommendations[].rationale` | string | желательно | Обоснование для врача: почему, зачем, на чём основано |
| `recommendations[].guideline_ref` | string | желательно | Ссылка на клинические рекомендации Минздрава |
| `recommendations[].patient_text` | string, непустая | да | Понятный текст для пациента: без диагноза, без находок, без пугающих формулировок |
| `recommendations[].already_booked` | boolean | да | Пациент уже записан на эту услугу (по `appointments`) |

```json
{
  "urgency": "priority",
  "catalog_version": "2026.10",
  "guidelines_version": "2026.09",
  "recommendations": [
    {
      "service_code": "ONC-MAMMO-CONSULT",
      "service_name": "Консультация онколога-маммолога",
      "importance": "high",
      "rationale": "BI-RADS 4 — показана консультация специалиста и решение вопроса о биопсии.",
      "guideline_ref": "КР МЗ РФ «Рак молочной железы»",
      "patient_text": "Рекомендуем консультацию маммолога, чтобы обсудить результаты обследования и дальнейшие шаги.",
      "already_booked": false
    }
  ]
}
```

## Проверки на стороне main-B2B

Ответ отклоняется и считается сбоем (с повтором), если:

- `urgency` не из списка допустимых значений;
- `catalog_version` или `guidelines_version` пустые;
- у любой рекомендации пустые `service_name` или `patient_text`, либо `importance` не из списка.

## Ошибки

Для ошибок рекомендуется JSON вида `{"error": "описание"}`. main-B2B логирует первые 1024 байта
тела любого не-200 ответа.
