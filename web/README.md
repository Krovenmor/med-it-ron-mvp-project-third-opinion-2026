# web – фронт «Маршрут после находки»

Интерфейсы пациента, врача, администратора и руководителя и демо-панель по [ТЗ на визуал MVP](../ТЗ%20на%20визуал%20MVP.md).

## Стек

React 19, TypeScript 6, Vite 8, React Router 8, TanStack Query 5, Tailwind CSS 4 (палитра и радиусы из ТЗ – токены в `src/styles/index.css`), lucide-react, sonner, Recharts 3 – графики дашборда. Страницы руководителя и пациента грузятся отдельными чанками. В проде статику отдаёт nginx.

## Запуск

Целиком со всеми сервисами – из корня репозитория:

```bash
docker compose up -d --build
```

Фронт: http://localhost:3000. nginx проксирует запросы к сервисам, поэтому CORS не нужен:

| Префикс | Куда |
|---|---|
| `/b2b/` | b2b-service |
| `/mis/` | mis-demo |
| `/b2c/` | b2c-service |

Адреса сервисов для nginx – в `config/docker.env`.

Разработка с горячей перезагрузкой (бэкенд поднят через compose):

```bash
npm install
npm run dev
```

Откроется http://localhost:5173, Vite проксирует те же префиксы на `localhost:8080`, `8081` и `8082` (`.env.development`).

| Команда | Что делает |
|---|---|
| `npm run dev` | dev-сервер |
| `npm run build` | проверка типов и сборка в `dist/` |
| `npm run typecheck` | только проверка типов |
| `npm run lint` | ESLint |

## Переменные окружения

| Переменная | Где | Описание |
|---|---|---|
| `VITE_DOCTOR_ID` | `.env.development`, `.env.production` | Идентификатор врача для заголовка `X-User-ID`; авторизации в MVP нет |
| `VITE_ADMIN_ID` | `.env.development`, `.env.production` | Идентификатор администратора для `X-User-ID` и фильтра «Мои» |
| `VITE_CLINIC_NAME` | `.env.development`, `.env.production` | Название клиники в скрипте звонка |
| `B2B_PROXY_TARGET`, `MIS_PROXY_TARGET`, `B2C_PROXY_TARGET` | `.env.development` | Куда dev-сервер проксирует запросы |
| `B2B_URL`, `MIS_URL`, `B2C_URL` | `config/docker.env` | Куда проксирует nginx в контейнере |

```

  shared/

    ui/         кнопки, бейджи, вкладки, переключатели, модальное окно, шторка, карточки, состояния загрузки
  features/
    demo/       демо-панель: роли, поступление из МИС, перемотка времени, сброс
    doctor/     очередь на проверку, карточка проверки, справка
    admin/      список «Позвонить», карточка звонка, журнал уведомлений
    manager/    дашборд воронки: плашки, воронка, динамика, разрезы, SLA, отказы, расчёт эффекта
```

## Что умеет роль «Пациент»

Данные – из `GET /b2c/api/v1/patients/{id}/route`: b2c-service отдаёт готовую модель экрана, фронт только рисует. Маршрут обновляется раз в 10 секунд. Вёрстка сначала мобильная: на телефоне вкладки внизу и карточка шага выезжает снизу, на десктопе вкладки сверху, сводка слева от дерева, карточка справа. Демо-пациент выбирается в шапке, адрес – `/patient/P-ANNA`.

- **Дерево:** SVG на временной шкале снизу вверх – линия на каждый день, даты справа, длинные пустые периоды сжаты в «⋯» с подписью, красная линия «Сегодня»; при открытии дерево прокручено к ней. Ствол с комлем – приёмы терапевта и исследования, ветки выходят из узла, где шаг назначили. Узлы: закрашенный – пройден, контур – записан, пунктир – назначен, терракотовый с «!» – срок прошёл. Ветки двухцветные, свет сверху-слева: зелёная – пройдено, жёлтая и коричневая – записан по отметке врача «Вторично» и «Приоритетно», серый пунктир – записи нет. При перемотке времени и после записи узлы и ветки меняются плавно. Легенда – в отдельном окне.
- **Сводка:** баннеры «Врач просит срочно связаться» (со звонком, без записи), «Врач готовит ваш план», «Отклонений не найдено»; прогресс плана с подписью «выполнение плана, а не состояние здоровья»; «Ближайший шаг» или «Срок прошёл, запишитесь»; телефон клиники с копированием номера и дисклеймер.
- **Карточка шага:** почему назначено, срок и отметка врача. «Записаться» – день и время из свободных слотов МИС, подтверждение, «Вы записаны». «Нужна помощь» – задача администратору «Просит перезвонить». «Не буду записываться» – причина, для «Другая причина» – комментарий. У записанного шага – «Добавить в календарь» (файл `.ics`), «Маршрут проезда», «Позвонить в клинику». Ссылка `?step=<id>` открывает карточку сразу, как из push или СМС.
- **Мои шаги, Записи, История:** шаги по сроку со статусами и кнопкой «Записаться»; предстоящие приёмы; пройденные приёмы и обследования. Строка открывает ту же карточку.
- **Настройки:** только макет – каналы, согласие, тихие часы, отзыв согласия.

## Что умеет роль «Врач»

- **Очередь на проверку:** сортировка по срочности и времени поступления, фильтры по срочности и статусу («Новый» / «В работе»), время ожидания и таймер SLA неотложных по бизнес-часам сервиса (учитывает перемотку времени). Очередь обновляется раз в 5 секунд; о новом неотложном кейсе – звук, всплывающее сообщение и браузерное уведомление.
- **Карточка проверки:** заключение, история приёмов из МИС (если МИС не ответила – пометка «история не загружена»), таблица рекомендаций с отметками «Приоритетно», «Вторично», «Не нужна» (с обязательной причиной) и текстом, который увидит пациент, – его можно поправить прямо в строке, в том числе до отметки. Добавление исследования из справочника услуг МИС, смена срочности (понижение – только с причиной), окно подтверждения с текстом ответственности.
- **Демо-панель:** «Симулировать поступление из МИС» сам дожидается, пока ИИ оценит новые заключения, и обновляет очередь без перезагрузки страницы.
- **Справка:** уровни срочности, отметки, дисклеймер.

## Что умеет роль «Администратор»

- **Позвонить:** активные задачи из протокола – неотложные сверху с пометкой «позвонить сейчас», затем просроченные. В строке – пациент с телефоном, что предложить и срок «не позднее», причина звонка, дедлайн по SLA, число попыток, статус и метка «Передать врачу» после трёх недозвонов. Фильтры по уровню, статусу и «Мои», кнопка «Взять в работу». Список обновляется раз в 5 секунд: если пациент записался сам, задача исчезает.
- **Карточка звонка:** скрипт без диагноза (обычный или неотложный) с подставленными клиникой, услугой, сроком и выбранным слотом; рекомендации врача с ближайшими слотами МИС – выбор слота и «Записал» записывают пациента через b2b-service. Результаты: «Не дозвонился», «Перезвонить позже» (быстрый выбор или своё время), «Дозвонился, закрыть», «Отказ» (причина обязательна, для «Другое» – комментарий), «Передать врачу»; общий комментарий и история попыток.
- **Журнал уведомлений:** что ушло бы пациенту (push, SMS) и сотрудникам (эскалации, передача врачу); строка раскрывает полный текст, фильтр «Пациентам» / «Сотрудникам».
- **Демо:** «+30 мин» и «+1 день» запускают таймеры протокола – эскалации неотложных, задачи «не записался вовремя», напоминания. Заодно двигаются часы mis-demo: прошедшие записи становятся визитами, и у пациента шаг засчитывается пройденным.

## Что умеет роль «Руководитель»

Дашборд только для чтения из `GET /api/v1/dashboard`, обновляется раз в 10 секунд. Цвета по гайду: текущий период – `#A7C957`, прошлый – графит, остальное серое, сетка `#D6DDE4`. На экране подпись «демо-данные»: «Сбросить демо» наполняет базу синтетической историей за 180 дней, а живые действия демо добавляются к ней.

- **Период:** 7, 30 или 90 дней, сравнение с прошлым периодом той же длины.
- **Плашки:** заключения, доля записавшихся после подтверждения врачом, SLA врача и администратора, доля записей через приложение – с изменением к прошлому периоду.
- **Воронка:** заключения → с находкой → подтверждено врачом → уведомлено → записались → пришли, у каждого шага доля от предыдущего.
- **Динамика:** поступившие заключения и записи по дням или неделям.
- **Разрезы:** конверсия в запись по срочности и модальности, каналы записи.
- **Выполнено вовремя:** SLA врача и администратора по уровням срочности.
- **Причины отказов:** записанные администраторами и указанные самими пациентами в приложении.
- **Расчёт эффекта:** исследований в месяц × доля с находкой × прирост конверсии × средний чек цепочки услуг. Доля с находкой и конверсия берутся из дашборда, остальное – редактируемые допущения.
