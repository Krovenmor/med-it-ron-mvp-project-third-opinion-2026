# b2b-service

Main-B2B «Маршрут после находки» — модульный монолит на Go: один бинарь и один процесс, но четыре изолированных модуля. Внешний API описан в [contracts/b2b-service.md](../../contracts/b2b-service.md).

## Модули

| Модуль | Владеет | Схема Postgres |
|---|---|---|
| `gateway` | Приём заключений из МИС, оценка ai-service, адаптер МИС для остальных модулей | `gateway` |
| `doctor` | Очередь и карточка врача, отметки, срочность, подтверждение, эскалация «кейс не открыт» | `doctor` |
| `care` | Маршрут после подтверждения: протокол таймеров, уведомления, задачи администратора, записи, план для b2c, дашборд | `care` |
| `system` | Бизнес-часы и демо: сброс и синтетическая история | — |

Разрез данных служит и безопасности: текст заключения и обоснования хранятся только в `gateway` и `doctor`, ФИО и телефоны — только в `gateway` и `care`. Врач видит пациента псевдонимно, администратор не видит диагноз.

## Правила границ

1. **Своя схема на модуль.** У модуля своя схема Postgres, свой пул соединений (`search_path` указывает на схему), свои миграции и SQL. Чужие таблицы недоступны физически: запрос из модуля не увидит таблицы соседа.
2. **Своя транзакция на модуль.** У каждого модуля собственный менеджер транзакций со своим ключом в контексте. Транзакция одного модуля не может случайно затянуть запросы другого.
3. **Сосед доступен только через его `api`.** Это интерфейсы для синхронных вызовов и контракты событий. Домен, сервисы и хранилище соседа импортировать нельзя. Правило проверяет тест `internal/modules/boundaries_test.go`.
4. **Синхронные вызовы — только чтение и действия без общей транзакции:**
   - `care` → `gateway`: слоты и запись в МИС;
   - `doctor` → `gateway`: история пациента;
   - `gateway` → `care`: активные услуги пациента для запроса в ai-service.
5. **Изменения передаются событиями через transactional outbox.**
   - Событие пишется в таблицу `jobs` модуля-источника в той же транзакции, что и изменение.
   - Воркер модуля доставляет его подписчикам с ретраями.
   - Подписчик обрабатывает событие в своей транзакции и запоминает его ID в `inbox`, поэтому повторная доставка безопасна.
   - Событие, пришедшее раньше предыдущего (например, подтверждение раньше начала проверки), возвращает ошибку и доставляется повторно позже.
6. **Таймеры считаются от времени события, а не от момента доставки.** Иначе задержка доставки или перемотка демо-часов сдвигает протокол.

## События

| Тема | Источник | Подписчик | Зачем |
|---|---|---|---|
| `gateway.patient_registered` | gateway | care | контакты пациента |
| `gateway.report_received` | gateway | care | кейс в воронке с момента поступления |
| `gateway.case_assessed` | gateway | doctor | кейс с оценкой ИИ в очередь врача |
| `doctor.review_started` | doctor | care | маршрут, неотложный протокол |
| `doctor.urgency_changed` | doctor | care | старт или снятие неотложного протокола |
| `doctor.case_confirmed` | doctor | care | план пациента без диагноза, таймеры после подтверждения |
| `doctor.review_escalated` | doctor | care | уведомление дежурному врачу в журнал |

## Структура

```
internal/
  platform/   инфраструктура без домена: часы, Postgres по схемам, jobs и воркер,
              события (outbox, inbox, шина), HTTP-обвязка, категории ошибок
  modules/
    <module>/
      api/        публичный контракт: интерфейсы и события
      domain/     модель модуля
      service/    сценарии
      infra/      postgres (миграции, SQL, репозитории), клиенты внешних систем
      transport/  HTTP-ручки модуля
      module.go   fx-модуль: всё внутреннее приватно, наружу — только api и роуты
  di/         сборка: core, platform и список модулей
```

## Как вынести модуль в отдельный сервис

Пример — `care`:

1. Новый бинарь `cmd/care` собирает `platform` и `care.Module`. Схему `care` переносим в отдельную базу, сменив DSN.
2. Синхронный порт `gatewayapi.MIS` реализуем HTTP-клиентом к gateway, а `careapi.Routes` в gateway — HTTP-клиентом к care. Код модулей не меняется: они зависят от интерфейсов.
3. Доставку `events.Delivery` переключаем с in-process шины на брокер. Подписки и inbox остаются прежними.
4. Демо: `system` вызывает сброс сервисов по HTTP, бизнес-часы раздаются тем же путём.

```bash
docker compose up -d --build          # из корня репозитория
go test ./internal/...                # тест границ модулей

```
