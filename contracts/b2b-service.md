# b2b-service (main-B2B) API

Базовый адрес: `http://localhost:8080`. Общие соглашения, коды ответов и справочник значений — в [README](README.md).

| Метод и путь | Назначение | Потребитель |
|---|---|---|
| `POST /api/v1/reports` | Приём заключения | МИС |
| `GET /api/v1/clock` | Бизнес-время сервиса | веб врача |
| `GET /api/v1/cases/{id}` | Карточка кейса | веб врача |
| `GET /api/v1/cases/{id}/history` | История приёмов пациента из МИС | веб врача |
| `GET /api/v1/review/queue` | Очередь проверки | веб врача |
| `POST /api/v1/cases/{id}/open` | Врач открыл кейс | веб врача |
| `PATCH /api/v1/cases/{id}/recommendations/{rec_id}` | Отметка рекомендации | веб врача |
| `POST /api/v1/cases/{id}/recommendations` | Своя рекомендация врача | веб врача |
| `PUT /api/v1/cases/{id}/urgency` | Смена срочности | веб врача |
| `POST /api/v1/cases/{id}/confirm` | Подтверждение кейса | веб врача |
| `GET /api/v1/patients/{external_id}/plan` | План пациента | b2c-service |

| `POST /demo/reset` | Сброс демо-данных | демо-кнопки |

## Приём заключения

`POST /api/v1/reports`

Создаёт кейс в статусе `draft` и ставит его на фоновую оценку ai-service. После оценки кейс переходит в `in_review` и появляется в очереди врача.

| Поле | Тип | Обязательно | Описание |
|---|---|---|---|
| `source_system` | string | да | Идентификатор МИС-источника |
| `study.id` | string | да | ID исследования в МИС; вместе с `source_system` — ключ идемпотентности |
| `study.modality` | `CT` \| `DX` \| `MG` | да | Модальность |
| `study.body_site` | string | нет | Область исследования |
| `study.performed_at` | RFC 3339 | да | Дата и время исследования |
| `conclusion` | string | да | Заключение ИИ по исследованию |
| `patient.id` | string | да | ID пациента в МИС |
| `patient.full_name` | string | да | ФИО |
| `patient.birth_date` | `YYYY-MM-DD` | да | Дата рождения |
| `patient.sex` | `male` \| `female` | да | Пол |
| `patient.phone` | string | нет | Телефон |
| `patient.email` | string | нет | Email |

```json
{
  "source_system": "mis-demo",
  "study": {
    "id": "MG-2026-0001",
    "modality": "MG",
    "body_site": "breast",
    "performed_at": "2026-10-03T09:00:00Z"
  },
  "conclusion": "Маммография обеих молочных желез. В верхне-наружном квадранте левой молочной железы образование неправильной формы 12 мм с нечёткими контурами. Заключение: BI-RADS 4.",
  "patient": {
    "id": "P-ANNA",
    "full_name": "Анна Смирнова",
    "birth_date": "1974-03-12",
    "sex": "female",
    "phone": "+79990000001",
    "email": "anna@example.com"
  }
}
```

Ответ:

```json
{ "case_id": "6b9a5672-0028-4a5e-896e-defdef2ebf8f", "status": "draft" }
```

| Код | Когда |
|---|---|
| 201 | Кейс создан |
| 200 | Исследование уже принято с тем же содержимым; в ответе существующий кейс и его текущий статус. ФИО, дата рождения, пол и контакты пациента обновляются |
| 400 | Некорректный JSON; не заполнено обязательное поле; `modality` или `sex` вне списка; дата не в нужном формате |
| 409 | Исследование уже принято, но отличается пациент, модальность, область, дата исследования или текст заключения |

Повтор считается тем же исследованием, если совпадают `patient.id`, `modality`, `body_site`, `performed_at` и `conclusion`.

## Карточка кейса

`GET /api/v1/cases/{id}`

Полные данные для врача, включая текст заключения и обоснования рекомендаций. Пациенту этот ответ не показывается.

```json
{
  "id": "6b9a5672-0028-4a5e-896e-defdef2ebf8f",
  "patient_id": "cdf7735e-a6bc-4b28-9866-77c313076611",
  "source_system": "mis-demo",
  "study_id": "MG-2026-0001",
  "modality": "MG",
  "body_site": "breast",
  "performed_at": "2026-10-03T09:00:00Z",
  "conclusion": "Маммография обеих молочных желез. … Заключение: BI-RADS 4.",
  "status": "in_review",
  "urgency": "priority",
  "catalog_version": "2026.10",
  "guidelines_version": "2026.09",
  "received_at": "2026-10-04T06:34:03.562141Z",
  "updated_at": "2026-10-04T06:34:03.878396Z",
  "patient": {
    "id": "P-ANNA",
    "full_name": "Анна Смирнова",
    "birth_date": "1974-03-12",
    "sex": "female"
  },
  "recommendations": [
    {
      "id": "28b9191c-c1f5-4987-9bad-00223872764a",
      "position": 1,
      "source": "ai",
      "service_code": "ONC-MAMMO-CONSULT",
      "service_name": "Консультация онколога-маммолога",
      "importance": "high",
      "rationale": "BI-RADS 4 — показана консультация специалиста и решение вопроса о биопсии.",
      "guideline_ref": "КР МЗ РФ «Рак молочной железы»",
      "patient_text": "Рекомендуем консультацию маммолога, чтобы обсудить результаты обследования и дальнейшие шаги.",
      "already_booked": false,
      "review": {
        "mark": "rejected",
        "reject_reason": "other",
        "reject_comment": "уже наблюдается у онколога",
        "reviewed_by": "dr-ivanova",
        "reviewed_at": "2026-10-04T07:10:00Z"
      }
    }
  ]
}
```

| Поле | Описание |
|---|---|
| `patient.id` | ID пациента в МИС |
| `urgency`, `catalog_version`, `guidelines_version` | Отсутствуют, пока ai-service не оценил кейс |
| `recommendations` | Отсортированы по `position`; пустой массив, если рекомендаций нет |
| `recommendations[].service_code` | `""` — услуги нет в клинике |
| `recommendations[].review` | `null`, пока врач не отметил рекомендацию; `reject_reason` и `reject_comment` есть только у отклонённых |

| Код | Когда |
|---|---|
| 200 | Кейс найден |
| 404 | Кейса нет или `id` не UUID |

## История приёмов пациента

`GET /api/v1/cases/{id}/history`

b2b-service запрашивает историю пациента кейса в МИС в момент вызова.

```json
{
  "visits": [
    { "service_code": "MG-SCREENING", "service_name": "Маммография (скрининг)", "visited_at": "2025-09-15T09:00:00Z" }
  ],
  "appointments": [
    { "service_code": "PULM-CONSULT", "service_name": "Консультация пульмонолога", "scheduled_at": "2026-10-05T06:00:00Z" }
  ]
}
```

| Код | Когда |
|---|---|
| 200 | История получена; массивы могут быть пустыми |
| 404 | Кейса нет |
| 502 | МИС недоступна или ответила ошибкой |

## Бизнес-время

`GET /api/v1/clock`

Текущее время сервиса с учётом демо-перемотки. Таймеры ожидания и SLA на фронте считаются от него, а не от часов браузера.

```json
{ "now": "2026-10-04T07:04:34.383389Z" }
```

## Проверка врачом

Все действия, кроме чтения очереди, требуют заголовок `X-User-ID`: без него — 401. Изменения возможны только пока кейс в статусе `in_review`, иначе — 409 с описанием текущего статуса.

### Очередь

`GET /api/v1/review/queue`

Кейсы в статусе `in_review`. Порядок: сначала по срочности (`emergency`, `priority`, `planned`, `normal`), внутри уровня — по времени поступления.

```json
{
  "cases": [
    {
      "case_id": "68b07f74-b201-4b05-b8ce-e969ea05b263",
      "urgency": "emergency",
      "modality": "DX",
      "performed_at": "2026-10-03T09:00:00Z",
      "received_at": "2026-10-04T06:34:03.601Z",
      "patient": { "id": "P-SERGEY", "full_name": "Сергей Иванов", "birth_date": "1988-07-20", "sex": "male" },
      "recommendations_total": 1,
      "recommendations_reviewed": 0,
      "opened_at": "2026-10-04T06:40:12Z"
    }
  ]
}
```

`opened_at` – когда врач впервые открыл кейс (`POST .../open`); поля нет, пока кейс не открывали.

### Врач открыл кейс

`POST /api/v1/cases/{id}/open`

Фиксирует в аудите, что врач взял кейс в работу. По этому событию будет строиться эскалация «врач не открыл неотложный кейс за 30 минут». Тело запроса не нужно, ответ без тела.

| Код | Когда |
|---|---|
| 204 | Событие записано |
| 401 | Нет `X-User-ID` |
| 404 | Кейса нет |
| 409 | Кейс не в `in_review` |

### Отметка рекомендации

`PATCH /api/v1/cases/{id}/recommendations/{rec_id}`

Частичное обновление: можно передать отметку, новый текст для пациента или и то и другое. Повторный вызов перезаписывает отметку. Текст можно править и до отметки: отметка при этом не меняется, в аудит пишется событие `recommendation_text_edited`.

| Поле | Тип | Обязательно | Описание |
|---|---|---|---|
| `mark` | `critical` \| `minor` \| `rejected` | если нет `patient_text` | Отметка врача |
| `reject_reason` | `contraindicated` \| `other` | для `rejected` | Причина отклонения; для других отметок не передаётся |
| `reject_comment` | string | для `other` | Комментарий к причине «другое» |
| `patient_text` | string | если нет `mark` | Исправленный текст для пациента; не передан — текст не меняется; пустая строка — 400 |

```json
{ "mark": "critical", "patient_text": "Пожалуйста, запишитесь к маммологу в ближайшие дни." }
```

Ответ 200 — рекомендация в том же виде, что в карточке кейса. `review` заполнен, если рекомендация уже отмечена.

| Код | Когда |
|---|---|
| 200 | Отметка сохранена |
| 400 | Нет ни `mark`, ни `patient_text`; недопустимая отметка или причина; причина у неотклонённой рекомендации; `other` без комментария; пустой `patient_text` |
| 401 | Нет `X-User-ID` |
| 404 | Кейса нет или рекомендация принадлежит другому кейсу |
| 409 | Кейс не в `in_review` |

### Своя рекомендация врача

`POST /api/v1/cases/{id}/recommendations`

Добавляется в конец списка со `source: "doctor"` и сразу считается отмеченной. `importance` выводится из отметки: `critical` → `high`, `minor` → `low`.

| Поле | Тип | Обязательно | Описание |
|---|---|---|---|
| `service_name` | string | да | Название услуги или специалиста |
| `patient_text` | string | да | Текст для пациента |
| `mark` | `critical` \| `minor` | да | Отметка врача |
| `service_code` | string | нет | Код услуги из каталога; без него услуга считается недоступной в клинике |
| `rationale` | string | нет | Обоснование для коллег |

```json
{
  "service_name": "Консультация онколога",
  "patient_text": "Рекомендуем консультацию онколога для обсуждения результатов.",
  "mark": "minor"
}
```

Ответ 201 — созданная рекомендация.

| Код | Когда |
|---|---|
| 201 | Рекомендация добавлена |
| 400 | Нет `service_name` или `patient_text`; `mark` не `critical`/`minor` |
| 401 | Нет `X-User-ID` |
| 404 | Кейса нет |
| 409 | Кейс не в `in_review` |

### Смена срочности

`PUT /api/v1/cases/{id}/urgency`

| Поле | Тип | Обязательно | Описание |
|---|---|---|---|
| `urgency` | `normal` \| `planned` \| `priority` \| `emergency` | да | Новый уровень |
| `reason` | string | при понижении | Причина; попадает в аудит |

```json
{ "urgency": "planned", "reason": "очаг стабилен по сравнению с прошлым КТ" }
```

| Код | Когда |
|---|---|
| 204 | Срочность изменена |
| 400 | Неизвестное значение; уровень не меняется; понижение без причины |
| 401 | Нет `X-User-ID` |
| 404 | Кейса нет |
| 409 | Кейс не в `in_review` |

### Подтверждение кейса

`POST /api/v1/cases/{id}/confirm`

Переводит кейс в `confirmed`. После этого рекомендации с отметками `critical` и `minor` становятся видны пациенту. Тело запроса не нужно.

```json
{ "case_id": "6b9a5672-0028-4a5e-896e-defdef2ebf8f", "status": "confirmed" }
```

| Код | Когда |
|---|---|
| 200 | Кейс подтверждён |
| 401 | Нет `X-User-ID` |
| 404 | Кейса нет |
| 409 | Кейс не в `in_review`; есть неотмеченные рекомендации (их число в описании ошибки) |

Параллельные подтверждения одного кейса безопасны: успешным будет ровно одно, остальные получат 409.

## Для b2c-service

### План пациента

`GET /api/v1/patients/{external_id}/plan?source_system={source_system}`

Пациентская выборка: только то, что можно показывать пациенту.

- Кейсы в статусах `confirmed`, `notified`, `booked`, `completed`, `declined`, `unreachable` — с рекомендациями, которые врач отметил как `critical` или `minor`.
- Неотложный кейс в статусах `in_review`, `confirmed`, `notified` — с флагом `urgent_contact: true`. До подтверждения врачом рекомендаций в нём нет, после подтверждения есть и флаг, и рекомендации.
- Кейсы в `draft` и остальные кейсы в `in_review` не попадают.

Кейсы отсортированы от новых исследований к старым.

```json
{
  "patient": { "full_name": "Анна Смирнова" },
  "cases": [
    {
      "case_id": "6b9a5672-0028-4a5e-896e-defdef2ebf8f",
      "status": "confirmed",
      "urgent_contact": false,
      "study": { "modality": "MG", "performed_at": "2026-10-03T09:00:00Z" },
      "recommendations": [
        {
          "id": "ebc65e72-26b8-4e68-ace0-63f164a3cce5",
          "service_code": "US-BREAST",
          "service_name": "УЗИ молочных желез",
          "patient_text": "Ультразвуковое исследование поможет врачу получить больше информации.",
          "mark": "critical"
        }
      ]
    }
  ]
}
```

| Код | Когда |
|---|---|
| 200 | План найден; `cases` может быть пустым |
| 400 | Нет `source_system` |
| 404 | Пациент неизвестен b2b-service |

### Регистрация записи

`POST /api/v1/cases/{id}/bookings`

Сообщает b2b-service, что пациент записан в МИС по рекомендации. Кейс переходит в `booked`, если ещё не там. Канал записи сохраняется для дашборда.

| Поле | Тип | Обязательно | Описание |
|---|---|---|---|
| `recommendation_id` | UUID | да | Рекомендация кейса, по которой записан пациент |
| `appointment_id` | string | да | ID записи в МИС; ключ идемпотентности |
| `scheduled_at` | RFC 3339 | да | Время приёма |
| `channel` | `self` \| `operator` | да | Кто записал |

```json
{
  "recommendation_id": "ebc65e72-26b8-4e68-ace0-63f164a3cce5",
  "appointment_id": "APT-0001",
  "scheduled_at": "2026-10-05T09:00:00+03:00",
  "channel": "self"
}
```

```json
{
  "booking_id": "0d3c9a6e-4b7e-4f53-9a2f-1f3f6f1c2b11",
  "case_id": "6b9a5672-0028-4a5e-896e-defdef2ebf8f",
  "recommendation_id": "ebc65e72-26b8-4e68-ace0-63f164a3cce5",
  "appointment_id": "APT-0001",
  "case_status": "booked"
}
```

| Код | Когда |
|---|---|
| 201 | Запись зарегистрирована |
| 200 | Запись с этим `appointment_id` уже зарегистрирована для той же рекомендации |
| 400 | Нет обязательного поля; `recommendation_id` не UUID; `scheduled_at` не RFC 3339; неизвестный `channel` |
| 404 | Кейса нет или рекомендация принадлежит другому кейсу |
| 409 | Кейс не в `confirmed`, `notified` или `booked`; рекомендация не подтверждена врачом или отклонена; услуги нет в клинике; `appointment_id` уже привязан к другой рекомендации |

## Демо

Ручки доступны только при `DEMO_MODE=true`, иначе 404.

### Перемотка времени

`POST /demo/clock/advance`

Сдвигает бизнес-время сервиса вперёд: таймеры, время поступления и событий считаются от сдвинутых часов. Сдвиг хранится в памяти и сбрасывается при перезапуске.

```json
{ "by": "30m" }
```

```json
{ "now": "2026-10-04T07:04:34.383389Z" }
```

| Код | Когда |
|---|---|
| 200 | Время сдвинуто; в ответе текущее бизнес-время |
| 400 | `by` не положительная длительность Go (`30m`, `24h`, `1h30m`) |

### Сброс демо

`POST /demo/reset`

Удаляет все данные сервиса (пациенты, кейсы, рекомендации, события, задачи, записи) и возвращает бизнес-время к текущему. Тело запроса не нужно. Ответ 204. Записи в mis-demo сбрасываются отдельно – `POST mis-demo /demo/reset`.
