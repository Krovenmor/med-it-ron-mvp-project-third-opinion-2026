# b2c-service API

Базовый адрес: `http://localhost:8082`. Общие соглашения, коды ответов и справочник значений — в [README](README.md).

b2c-service не хранит данных: на каждый запрос берёт план пациента из b2b-service и историю из МИС. `{patient_id}` во всех путях — ID пациента в МИС (например, `P-ANNA`).

| Метод и путь | Назначение |
|---|---|
| `GET /api/v1/patients/{patient_id}/route` | Маршрут пациента: всё для экранов «Дерево», «Мои шаги», «Записи», «История» |
| `GET /api/v1/patients/{patient_id}/recommendations/{rec_id}/slots` | Свободные слоты по рекомендации |
| `POST /api/v1/patients/{patient_id}/recommendations/{rec_id}/appointments` | Запись по рекомендации |
| `POST /api/v1/patients/{patient_id}/recommendations/{rec_id}/decline` | «Не буду записываться» |
| `POST /api/v1/patients/{patient_id}/recommendations/{rec_id}/help-requests` | «Нужна помощь»: просьба перезвонить |

## Маршрут пациента

`GET /api/v1/patients/{patient_id}/route`

Готовая модель экрана: b2c-service собирает её из плана b2b-service и истории МИС, а фронт только рисует. Все даты и «сегодня» — по бизнес-времени (`now`), поэтому перемотка демо-часов сразу сдвигает сроки и просрочки.

```json
{
  "now": "2026-10-04T12:00:00Z",
  "patient": { "full_name": "Игорь Петров" },
  "clinic": { "name": "Медитрон", "phone": "+7 (495) 123-45-67", "address": "Москва, ул. Садовая-Кудринская, 3" },
  "urgent_contact": false,
  "pending_review": false,
  "no_findings": false,
  "progress": 44,
  "next_step_id": "2b7e…",
  "trunk": [
    { "id": "visit:0", "kind": "visit", "title": "Приём терапевта", "date": "2026-09-30T07:00:00Z", "ai_report": false, "pending": false },
    { "id": "study:4aa4…", "kind": "study", "title": "Компьютерная томография", "date": "2026-10-02T06:00:00Z", "ai_report": true, "pending": false }
  ],
  "steps": [
    {
      "id": "2b7e…",
      "kind": "recommendation",
      "origin_id": "study:4aa4…",
      "case_id": "4aa4…",
      "title": "Контрольная КТ органов грудной клетки",
      "text": "Повторное исследование покажет, как изменилась картина со временем.",
      "mark": "minor",
      "status": "recommended",
      "late": false,
      "assigned_at": "2026-10-02T12:00:00Z",
      "due_at": "2026-11-01T12:00:00Z",
      "date": "2026-11-01T12:00:00Z",
      "in_clinic": true,
      "bookable": true,
      "appointment": null
    },
    { "id": "history:0", "kind": "visit", "origin_id": "visit:0", "title": "Общий анализ крови", "status": "done", "late": false, "date": "2026-10-01T06:00:00Z", "visited_at": "2026-10-01T06:00:00Z", "in_clinic": false, "bookable": false, "appointment": null }
  ],
  "appointments": [
    { "id": "APT-0002", "service_name": "Консультация пульмонолога", "scheduled_at": "2026-10-06T11:00:00+03:00" }
  ]
}
```

### Ствол и ветки

- **`trunk`** — ствол дерева по возрастанию даты:
  - приёмы первичного врача (терапевта) из МИС;
  - исследования, по которым работал сервис (`ai_report: true`; `pending: true` — врач ещё готовит план).
  - Если визит из истории раньше всего ствола, он становится корнем (`root:N`).
- **`steps`** — ветки. `origin_id` — узел ствола, из которого ветка выходит:
  - `kind: recommendation` — назначения врача, выходят из своего исследования;
  - `kind: visit` — прочие визиты из истории (анализы, консультации), выходят из ближайшего предыдущего узла ствола; всегда `done`.
- **`date`** — где узел стоит на шкале: пройден — дата визита, записан — дата приёма, иначе — срок `due_at`.

| `status` рекомендации | Когда |
|---|---|
| `done` | В МИС есть визит с той же услугой после исследования; `late: true` — позже срока |
| `booked` | Есть запись по направлению или на ту же услугу после исследования; `appointment` заполнен |
| `declined` | Пациент отказался, `decline_reason` — причина |
| `overdue` | Срок `due_at` прошёл, записи и визита нет |
| `recommended` | Остальное |

`bookable` — показать «Записаться». Нужно, чтобы шаг был `recommended` или `overdue`, услуга была в клинике (`in_clinic`), а кейс не был неотложным: при `urgent_contact` пациенту предлагают звонок, а не запись. У шагов такого кейса нет `due_at`: они не просрочиваются и не входят в прогресс, пока действует `urgent_contact`.

### Сводка

| Поле | Смысл |
|---|---|
| `urgent_contact` | Врач просит срочно связаться: баннер со звонком вместо записи |
| `pending_review` | Есть исследование, по которому врач ещё готовит план |
| `no_findings` | В последнем подтверждённом кейсе отклонений не найдено |
| `progress` | Прогресс плана в процентах или `null`, если считать пока нечего (см. ниже) |
| `next_step_id` | «Ближайший шаг»: сначала просроченные, затем ближайший срок; если открытых нет — ближайшая запись |
| `appointments` | Предстоящие записи для вкладки «Записи» |

**Прогресс** = Σ (вес × результат) ÷ Σ весов. Вес: `critical` — 3, `minor` — 1. Результат:
- пройден в срок — 1;
- пройден с опозданием — 0,5;
- срок прошёл без визита или пациент отказался — 0;
- срок не наступил и шаг не пройден — не учитывается.

Запись прогресс не меняет: меняет только пройденный приём.

| Код | Когда |
|---|---|
| 200 | Маршрут построен; если показать нечего, `trunk` и `steps` пустые |
| 404 | Пациент неизвестен b2b-service |
| 502 | b2b-service или МИС недоступны |

## Свободные слоты

`GET /api/v1/patients/{patient_id}/recommendations/{rec_id}/slots`

Ближайшие свободные слоты МИС по услуге из рекомендации.

```json
{
  "slots": [
    { "id": "PULM-CONSULT.202610051100", "starts_at": "2026-10-05T11:00:00+03:00" },
    { "id": "PULM-CONSULT.202610051400", "starts_at": "2026-10-05T14:00:00+03:00" }
  ]
}
```

`id` слота непрозрачен: его передают при записи как есть.

| Код | Когда |
|---|---|
| 200 | Слоты получены; список может быть пустым |
| 404 | Пациент неизвестен или у него нет такой подтверждённой рекомендации |
| 409 | Услуги нет в клинике (`in_clinic: false`) |
| 502 | b2b-service или МИС недоступны |

## Запись

`POST /api/v1/patients/{patient_id}/recommendations/{rec_id}/appointments`

```json
{ "slot_id": "PULM-CONSULT.202610051100" }
```

```json
{
  "id": "APT-0002",
  "service_name": "Консультация пульмонолога",
  "scheduled_at": "2026-10-05T11:00:00+03:00"
}
```

Что происходит:

1. Проверяется, что рекомендация подтверждена врачом, есть в клинике и ещё не записана.
2. Создаётся запись в МИС со ссылкой на рекомендацию.
3. Запись регистрируется в b2b-service (`POST /api/v1/cases/{id}/bookings`, канал `self`); кейс переходит в `booked`.

Если на шаге 3 b2b-service недоступен, ответ — 502, но запись в МИС уже создана. Повторный запрос по той же рекомендации вернёт 409 «уже записаны» и перед этим заново зарегистрирует существующую запись в b2b-service — так частичный сбой исправляется повторным нажатием.

| Код | Когда |
|---|---|
| 201 | Пациент записан |
| 400 | Некорректный JSON; нет `slot_id`; слот не существует или в прошлом |
| 404 | Пациент неизвестен или у него нет такой подтверждённой рекомендации |
| 409 | Услуги нет в клинике; по рекомендации уже есть запись; слот занят |
| 502 | b2b-service или МИС недоступны |

Перенос и отмена записи — после MVP.

## «Не буду записываться»

`POST /api/v1/patients/{patient_id}/recommendations/{rec_id}/decline`

```json
{ "reason": "far", "comment": "" }
```

`reason`: `expensive`, `far`, `other_clinic`, `not_needed`, `other` (для `other` нужен `comment`). Отказ записывается в b2b-service; если отказаны или записаны все шаги кейса, кейс закрывается отказом.

| Код | Когда |
|---|---|
| 204 | Отказ записан |
| 400 | Неизвестная причина; `other` без комментария |
| 404 | Пациент неизвестен или у него нет такой рекомендации |
| 409 | По шагу уже есть запись или отказ; кейс ещё на проверке |
| 502 | b2b-service недоступен |

## «Нужна помощь»

`POST /api/v1/patients/{patient_id}/recommendations/{rec_id}/help-requests`

Администратор получает задачу «Пациент просит перезвонить» по кейсу этой рекомендации. Повторный запрос новую задачу не создаёт. Тело не нужно, ответ 202.

| Код | Когда |
|---|---|
| 202 | Просьба передана |
| 404 | Пациент неизвестен или у него нет такой рекомендации |
| 502 | b2b-service недоступен |
