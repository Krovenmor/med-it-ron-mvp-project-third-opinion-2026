# b2c-service API

Базовый адрес: `http://localhost:8082`. Общие соглашения, коды ответов и справочник значений — в [README](README.md).

b2c-service не хранит данных: на каждый запрос берёт план пациента из b2b-service и историю из МИС. `{patient_id}` во всех путях — ID пациента в МИС (например, `P-ANNA`).

| Метод и путь | Назначение |
|---|---|
| `GET /api/v1/patients/{patient_id}/graph` | Граф здоровья |
| `GET /api/v1/patients/{patient_id}/recommendations/{rec_id}/slots` | Свободные слоты по рекомендации |
| `POST /api/v1/patients/{patient_id}/recommendations/{rec_id}/appointments` | Запись по рекомендации |

## Граф здоровья

`GET /api/v1/patients/{patient_id}/graph`

```json
{
  "patient": { "full_name": "Игорь Петров" },
  "clinic_phone": "+7 (495) 123-45-67",
  "nodes": [
    { "id": "study:4aa48e52-…", "type": "study", "title": "Компьютерная томография", "date": "2026-10-03T09:00:00Z" },
    {
      "id": "recommendation:9f1c…",
      "type": "recommendation",
      "title": "Консультация пульмонолога",
      "text": "Рекомендуем консультацию пульмонолога по результатам КТ.",
      "status": "booked",
      "mark": "critical",
      "in_clinic": true,
      "bookable": false
    },
    { "id": "appointment:APT-0001", "type": "appointment", "title": "Консультация пульмонолога", "date": "2026-10-05T09:00:00+03:00" },
    {
      "id": "recommendation:2b7e…",
      "type": "recommendation",
      "title": "Контрольная КТ органов грудной клетки через 3 месяца",
      "text": "Повторное исследование покажет, как изменилась картина со временем.",
      "status": "recommended",
      "mark": "minor",
      "in_clinic": true,
      "bookable": true
    }
  ],
  "edges": [
    { "from": "study:4aa48e52-…", "to": "recommendation:9f1c…" },
    { "from": "recommendation:9f1c…", "to": "appointment:APT-0001" },
    { "from": "study:4aa48e52-…", "to": "recommendation:2b7e…" }
  ]
}
```

### Узлы

`id` узла уникален в графе и имеет вид `<тип>:<id>`. Для рекомендаций после двоеточия стоит ID рекомендации — его передают в `rec_id` при запросе слотов и записи.

| `type` | Поля | Смысл |
|---|---|---|
| `study` | `title` (название модальности), `date` (дата исследования) | Корень ветки, по узлу на кейс |
| `urgent_contact` | `title`, `text` с телефоном клиники | Неотложный кейс: врач просит срочно связаться с клиникой. Показывается до и после подтверждения врачом |
| `recommendation` | `title` (услуга), `text` (текст для пациента), `status`, `mark`, `in_clinic`, `bookable` | Подтверждённая врачом рекомендация |
| `appointment` | `title`, `date` (время приёма) | Запись в МИС |
| `visit` | `title`, `date` (дата визита) | Состоявшийся визит |

Поля, которых у типа нет, в JSON отсутствуют. `in_clinic` и `bookable` есть только у рекомендаций.

| Поле рекомендации | Значения |
|---|---|
| `status` | `recommended` — записи нет; `booked` — есть запись; `done` — визит состоялся |
| `mark` | `critical` — крайне важна, `minor` — менее важна |
| `in_clinic` | `false` — услуги нет в клинике: показать совет обратиться к профильному специалисту и `clinic_phone` |
| `bookable` | `true` — показать кнопку записи (`in_clinic` и `status: recommended`) |

### Рёбра

`study → recommendation`, `study → urgent_contact`, `recommendation → appointment` или `recommendation → visit`. Порядок узлов и рёбер стабилен: ветки идут в порядке кейсов из b2b-service, рекомендации — в порядке врача.

### Как определяется статус рекомендации

1. **`done`** — в МИС есть визит с той же услугой (`service_code`) позже даты исследования.
2. **`booked`** — в МИС есть запись со ссылкой на эту рекомендацию. Если такой нет — запись на ту же услугу позже даты исследования без ссылки на другую рекомендацию (например, пациент записался по телефону).
3. Иначе **`recommended`**.

Один визит или одна запись засчитывается только одной рекомендации.

| Код | Когда |
|---|---|
| 200 | Граф построен; если показать нечего, `nodes` и `edges` пустые |
| 404 | Пациент неизвестен b2b-service |
| 502 | b2b-service или МИС недоступны |

## Свободные слоты

`GET /api/v1/patients/{patient_id}/recommendations/{rec_id}/slots`

Ближайшие свободные слоты МИС по услуге из рекомендации.

```json
{
  "slots": [
    { "id": "PULM-CONSULT.202610051100", "starts_at": "2026-10-05T11:00:00+03:00" },
    { "id": "PULM-CONSULT.202610051400", "starts_at": "2026-10-05T14:00:00+03:00" }
  ]
}
```

`id` слота непрозрачен: его передают при записи как есть.

| Код | Когда |
|---|---|
| 200 | Слоты получены; список может быть пустым |
| 404 | Пациент неизвестен или у него нет такой подтверждённой рекомендации |
| 409 | Услуги нет в клинике (`in_clinic: false`) |
| 502 | b2b-service или МИС недоступны |

## Запись

`POST /api/v1/patients/{patient_id}/recommendations/{rec_id}/appointments`

```json
{ "slot_id": "PULM-CONSULT.202610051100" }
```

```json
{
  "id": "APT-0002",
  "service_name": "Консультация пульмонолога",
  "scheduled_at": "2026-10-05T11:00:00+03:00"
}
```

Что происходит:

1. Проверяется, что рекомендация подтверждена врачом, есть в клинике и ещё не записана.
2. Создаётся запись в МИС со ссылкой на рекомендацию.
3. Запись регистрируется в b2b-service (`POST /api/v1/cases/{id}/bookings`, канал `self`); кейс переходит в `booked`.

Если на шаге 3 b2b-service недоступен, ответ — 502, но запись в МИС уже создана. Повторный запрос по той же рекомендации вернёт 409 «уже записаны» и перед этим заново зарегистрирует существующую запись в b2b-service — так частичный сбой исправляется повторным нажатием.

| Код | Когда |
|---|---|
| 201 | Пациент записан |
| 400 | Некорректный JSON; нет `slot_id`; слот не существует или в прошлом |
| 404 | Пациент неизвестен или у него нет такой подтверждённой рекомендации |
| 409 | Услуги нет в клинике; по рекомендации уже есть запись; слот занят |
| 502 | b2b-service или МИС недоступны |

Перенос и отмена записи — после MVP.
